# 项目跟进路线图

目标不是继续堆功能，而是把 OnCallPilot 打磨成一份可信的个人 Agent 作品。

## 第一优先级：修正作品集可信度

已完成：

- 重写 `docs/agent-portfolio.md`，去掉乱码和过度包装。
- 重写 `docs/job-fit-analysis.md`，区分已体现、部分体现、未体现。
- 重写 `docs/prompt-tuning-log.md`，区分已验证记录和待补样例。
- 调整 `docs/resume-verification-report.md`，避免把本地样例指标说成生产结果。

原则：

- 能复现的才写成“已验证”。
- 只有想法或模板的写成“待补”。
- 本地样例集指标必须标注样例范围。

## 第二优先级：补 Prompt 调优证据链

围绕 `ai_ops` 补 5 条 bad case：

1. 不查日志直接下结论。
2. 工具顺序不稳定。
3. 输出格式不稳定。
4. 工具空结果后编造。
5. 处理建议缺失。

每条必须包含：

- 输入。
- 原输出。
- 问题。
- 修改策略。
- 新输出。
- 证据位置。

## 第三优先级：补 A/B 对比

### 实验 1：单 Agent vs Planner-Executor

指标：

- 是否完成所有排查步骤。
- 平均工具调用次数。
- 报告结构完整率。
- 是否引用证据。

### 实验 2：无 rerank vs 有 rerank

指标：

- hit@1。
- hit@k。
- MRR。
- 返回 chunk 是否包含期望 SOP。

### 实验 3：只用本地工具 vs MCP + 本地 fallback

指标：

- 工具调用成功率。
- 失败时是否能降级。
- 报告是否说明证据来源。

## 第四优先级：补展示材料

至少准备：

1. README 首页截图。
2. AIOps 一次完整运行截图。
3. Prompt 调优 before / after 截图。
4. RAG 评测报告截图。

## 第五优先级：平台版轻量 workflow

如果时间允许，再做一个 Dify / Coze / 扣子版本。不要重做完整项目，只复刻最小链路：

1. 输入告警。
2. 查询日志工具。
3. 查询知识库工具。
4. 输出标准化报告。

这个版本用于证明你不仅会 Java 工程，也理解平台型 Agent workflow。

## 两周执行版

### 第 1 周

1. 跑通 3 个标准告警案例。
2. 保存运行截图。
3. 补 5 条 prompt tuning 记录。
4. 产出一版可投递作品集 Markdown。

### 第 2 周

1. 补 A/B 对比。
2. 做一个轻量平台 workflow。
3. 把 README 改成更像作品展示页。

## 面试前必须能回答的 3 个问题

### 1. 为什么这样设计多 Agent？

要能说清：

- 为什么不直接单 Agent。
- 为什么拆 Planner / Executor。
- 这样解决了什么可解释性和可控性问题。

### 2. 你调过什么？

要能说清：

- 调前是什么问题。
- 改了哪条 prompt、路由或工具策略。
- 调后有什么变化。

### 3. 怎么证明它更好了？

要能说清：

- 用了什么指标。
- 用了什么 bad case。
- 对比结果是什么。

## 结论

项目已经有可投递的工程基础，但真正贴近岗位的不是继续加模块，而是补证据链：Prompt 调优、bad case、A/B 对比和可复现演示。
