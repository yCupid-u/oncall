# 错误率升高告警处理方案

## 告警名称

- **告警名**: `HighErrorRate`
- **告警级别**: 严重
- **触发条件**: 5xx 错误率持续高于阈值，或核心接口错误量突增。

## 问题描述

错误率升高通常与版本发布、配置变更、依赖异常、数据库连接失败、流量突增或参数兼容问题有关。排障重点是先按接口、实例、版本和错误类型聚合，再判断是否需要回滚、降级或修复依赖。

## 检索关键词

`HighErrorRate`、`5xx`、`exception`、`rollback`、`release`、`dependency error`、`NullPointerException`、`connection refused`

## 排查步骤

### 步骤 1：查询错误日志

- 工具：`queryLogs`
- 日志主题：`application-logs`
- 查询条件示例：`level:ERROR OR status >= 500`
- 重点字段：`service_name`、`api`、`status`、`exception`、`version`、`instance_id`、`trace_id`

### 步骤 2：按维度聚合

优先聚合：

- API 路径
- 错误类型
- 服务版本
- 实例 ID
- 下游依赖名称

### 步骤 3：关联发布和配置变更

- 如果错误集中在新版本，优先考虑回滚。
- 如果错误集中在某个实例，优先摘除异常实例。
- 如果错误集中在下游调用，转入下游依赖排查。

## 常见原因

### 原因 1：新版本发布引入缺陷

特征：

- 错误率从发布时间点开始上升。
- 错误集中在新版本实例。
- 日志出现空指针、参数解析失败或兼容性异常。

处理：

1. 立即回滚到上一稳定版本。
2. 保留异常日志和请求样本。
3. 对发布流程增加灰度和自动回滚策略。

### 原因 2：下游依赖不可用

特征：

- 日志出现 `connection refused`、`timeout`、`503`。
- 多个上游服务同时报错。
- 错误链路集中在同一依赖。

处理：

1. 开启熔断和降级。
2. 切换备用依赖或读缓存。
3. 通知依赖负责人并同步影响范围。

### 原因 3：请求参数或数据异常

特征：

- 错误集中在特定用户、租户或参数组合。
- 日志出现参数校验失败、JSON 解析失败或数据不存在。
- 不是所有接口都受影响。

处理：

1. 增加参数校验和默认值。
2. 对异常数据做临时修复。
3. 增加输入样本到回归测试。

## 应急处理

1. 新版本导致错误时优先回滚。
2. 下游不可用时启用降级和熔断。
3. 对异常入口限流，保护核心链路。
4. 对单实例异常先摘流，再保留日志排查。

## 验证方式

1. 5xx 错误率恢复到阈值以下。
2. 核心接口成功率恢复。
3. 告警不再触发。
4. 回滚或修复版本完成后观察至少 30 分钟。
