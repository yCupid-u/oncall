# 项目跟进路线图

目标是把 OnCallPilot 打磨成一份更完整的 Agent 工程作品集：既能跑通核心链路，也能展示调优、评测和工程设计能力。

## 第一优先级：完善可投递材料

已完成：

- 重写 `README.md`，突出项目能力、技术栈、运行方式和展示口径。
- 重写 `docs/agent-portfolio.md`，整理 Agent 作品集说明。
- 重写 `docs/job-fit-analysis.md`，映射岗位要求和项目证据。
- 重写 `docs/resume-verification-report.md`，整理简历表述和验证命令。

原则：

- 重点展示可运行链路、可验证代码和可扩展设计。
- 指标、截图和测试结果尽量落到文件或命令，减少口头描述。
- 面试材料使用“已实现 / 可增强 / 后续计划”的正向表达。

## 第二优先级：补 Prompt 调优证据链

围绕 `ai_ops` 补 5 条 bad case：

1. 不查日志直接下结论。
2. 工具顺序不稳定。
3. 输出格式不稳定。
4. 工具空结果后编造。
5. 处理建议缺少优先级。

每条包含：

- 输入
- 原输出
- 问题
- 修改策略
- 新输出
- 证据位置

## 第三优先级：补 A/B 对比

### 实验 1：单 Agent vs Planner-Executor

指标：

- 是否完成全部排查步骤
- 平均工具调用次数
- 报告结构完整率
- 是否引用证据

### 实验 2：无 rerank vs 有 rerank

指标：

- hit@1
- hit@k
- MRR
- 返回 chunk 是否包含期望 SOP

### 实验 3：本地工具 vs MCP + 本地 fallback

指标：

- 工具调用成功率
- 失败时是否能降级
- 报告是否说明证据来源

## 第四优先级：补展示材料

至少准备：

1. README 首页截图。
2. AIOps 一次完整运行截图。
3. Prompt 调优 before / after 截图。
4. RAG 评测报告截图。

## 第五优先级：平台版轻量 workflow

如果时间允许，再做一个 Dify / Coze / 扣子版本。不要重做完整项目，只复刻最小链路：

1. 输入告警。
2. 查询日志工具。
3. 查询知识库工具。
4. 输出标准化报告。

这个版本用于证明你不只会 Java 工程，也理解平台型 Agent workflow。

## 两周执行版

### 第 1 周

1. 跑通 3 个标准告警案例。
2. 保存运行截图。
3. 补 5 条 Prompt tuning 记录。
4. 产出一版可投递作品集 Markdown。

### 第 2 周

1. 补 A/B 对比。
2. 做一个轻量平台 workflow。
3. 把 README 改成更像作品展示页。

## 面试前必须能回答的 3 个问题

### 1. 为什么这样设计多 Agent？

要能说清：

- 为什么不直接单 Agent。
- 为什么拆 Planner / Executor。
- 这样解决了什么可解释性和可控性问题。

### 2. 你调过什么？

要能说清：

- 调前是什么问题。
- 改了哪条 prompt、路由或工具策略。
- 调后有什么变化。

### 3. 怎么证明它更好了？

要能说清：

- 用了什么指标。
- 用了什么 bad case。
- 对比结果是什么。

## 结论

项目已经具备可投递的工程基础。下一步重点是把运行记录、Prompt 调优、bad case、A/B 对比和截图证据补齐，让面试官能快速看到“亲手做过、跑通过、调优过”的过程。
